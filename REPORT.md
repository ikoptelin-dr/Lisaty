Дата: 11.11.2026.

## Главное

**Папка `inputs/` пуста.** В репозитории нет ни одного документа: ни спецификаций, ни CoA, ни СГР,
ни сертификатов, ни КП, ни анкет, ни переписки. Поэтому:

- подтверждено документами — **0 утверждений из 35**;
- чистовая сборка (`node build/build.mjs`) **падает**, и так и должно быть: на ней 62 ошибки — 34 ссылки на неподтверждённые утверждения, 5 незаполненных контактов и т. д.;
- собран **черновик** (`--draft`): та же вёрстка, но вместо каждого факта стоит «по запросу», на каждой странице плашка «Черновик… не для рассылки», в HTML стоит `noindex`. Ни одно неподтверждённое утверждение в файлы не попало — это проверяет скрипт.

Черновик можно показать заводу и коллегам как макет. Рассылать нельзя: закупщику он ничего не даёт.

## Что убрано из-за отсутствия документов

Всё фактическое. На месте каждого факта стоит «по запросу», а в `gaps.md` есть номер вопроса к заводу:

- **Производитель** (наименование, адрес) — G-01. Даже это требует карточки предприятия.
- **Названия продуктов, число штаммов, виды** («БифиЛиз», «ЛактоЛиз», «ПропиоЛиз») — G-02…G-04.
  Замечено: «ЛактоЛиз 6–8 штаммов» — для спецификации диапазон не годится; названия видов
  устарели (L. fermentum, L. bulgaricus, P. shermanii переименованы в 2020 г.).
- **Технология, форма, носитель, консервант** — G-05, G-06.
- **Аллерген (молоко)** — G-07. Это вывод из «носитель — сыворотка», а не документ.
- **Назначение / область применения** — G-08.
- Запрещённое заданием без документа: **количественный состав, инактивация, срок годности и хранение,
  сертификаты и их область действия, мощность, цены, эффективность** — G-09…G-15, G-19, G-20, G-24.
- **Cavitol, ProteoLyse, «ФерЛиз Про»** — не включены: спецификаций нет. Для них подготовлен бриф директору по науке `dist/brief_science_director.docx`.

Ещё поймано и убрано во время сборки:
- meta description перечисляла группы бактерий без документа — переписана;
- заголовок «Три продукта» утверждал число продуктов — заменён на «Продукты»;
- в PDF нумерованный список давал числа 1–2–3, которых нет в HTML — сверка это поймала, список заменён.

## Что сделать дальше

1. Отправить заводу письмо и вопросы из `gaps.md`.
2. Положить ответы в `inputs/`. Для каждого факта в `claims.yaml` указать `source.file`, `source.page` и поставить `status: "подтверждено"`.
3. Заполнить `contacts` в `content.yaml`, в том числе адрес обработчика формы.
4. `node build/review_sheet.mjs` → отдать `review_plant.md` технологу на подпись.
5. Отдать `regulatory_review.md` специалисту по регистрации.
6. `node build/build.mjs && node build/check_numbers.mjs && node build/lighthouse.mjs`.
7. Провести `test_buyers.md` на чистовой версии.

## Ограничения сборки

- Линтер ищет факты по признакам (цифры, латинские названия видов, единицы, сертификаты, «соответствует» и т. п.).
  Факт без этих признаков он может пропустить — так и вышло с «Три продукта». Поэтому `review_plant.md`
  и чтение глазами остаются обязательными.
- Форма — статическая. Без адреса обработчика она никуда не отправляет; чистовая сборка не пройдёт, пока адрес не указан.
